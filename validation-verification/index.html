Validation & Verification

Become a data-quality detective: find bad data, design rules, repair algorithms and prove what your checks can—and cannot—do.

StarterSix checksDesignPseudocodeVerificationExamExit ticket

🎯 Your mission

By the end, you should be able to explain the difference between validation and verification; choose among six validation checks; explain visual and double-entry verification; and write pseudocode or flowcharts using these checks.

Remember: Validation checks rules. Verification checks that data has been transferred or entered accurately. Neither guarantees the original information is true.
00–05 min · Think–pair–share

1. The bad data challenge

Which values might be invalid? Discuss what rule would detect each one.

Age: 250
Name: (blank)
Exam mark: 125
Email: student.school.com
Siblings: Three
Student ID: AB12

Think deeper: A student scores 56 but the teacher types 65. Would a range check detect this?

Reveal discussion answer

No. Both marks are within 0–100. A range check validates the value's plausibility but does not detect that the wrong mark was entered.

05–17 min · Group investigation

2. Validation detectives

Predict each definition before opening its card. Explain an example to your group.

Range checkChecks a value is within permitted limits. Example: marks from 0 to 100 inclusive.
Length checkChecks the number of characters. Example: an ID has exactly 8 characters.
Type checkChecks the data type. Example: siblings must be an integer.
Presence checkChecks that a required field is not empty. Example: surname is mandatory.
Format checkChecks a specified pattern. Example: date in DD/MM/YYYY format (this pattern alone does not ensure a real date).
Check digitA digit calculated from other digits to help detect input or scanning errors. Example: ISBN-13.

Quick matching quiz

Stretch question

Can a field need more than one validation check? Yes: age could require presence, type and range checks. A four-digit PIN may require a length check and a format check restricting it to digits.

17–27 min · Group design

3. Build a school registration system

For each field, decide on checks, exact rules and an invalid example. Swap designs with another group and try to find a value that slips through.

FieldYour validation ruleRejected example

Challenge: Why can an email pass a format check but still not exist?

Possible rules (check after discussion)

Name: presence; age: integer type and suitable range; email: format and presence; date of birth: format plus actual calendar-date checks; student ID: length 8; examination score: numeric type and range 0–100; siblings: non-negative integer.

27–37 min · Pair programming

4. Algorithm repair workshop

A · Fix the range check

INPUT Mark
IF Mark >= 0 THEN
    OUTPUT "Valid mark"
ELSE
    OUTPUT "Invalid mark"
ENDIF

What happens for 150? Write the corrected condition.

B · Presence check

INPUT StudentName
IF StudentName ______ THEN
    OUTPUT "Name required"
ELSE
    OUTPUT "Name accepted"
ENDIF

C · Double-entry check

INPUT Password1
INPUT Password2
IF __________________ THEN
    OUTPUT "Entries match"
ELSE
    OUTPUT "Please re-enter password"
ENDIF

D · Flowchart challenge

Draw a flowchart that repeatedly asks for an age until an integer between 11 and 18 inclusive is entered. Use a decision symbol and a loop back to input.

Reveal suggested answers
IF Mark >= 0 AND Mark <= 100 THEN
IF StudentName = "" THEN
IF Password1 = Password2 THEN

For the flowchart: input age → decision “Is age an integer AND 11 ≤ age ≤ 18?” → if No, show error and return to input; if Yes, accept and end.

37–47 min · Role-play

5. Verification challenge

Partner A copies this record. Partner B visually compares it with the original. Then both independently enter the record and compare the two copies.

Source record

Student ID: ST482719
Exam mark: 78
Surname: Thompson

Matching entries do not prove the original information is correct. If the same mistake appears in both entries, the comparison may not detect it.

Discuss visual vs double-entry verification

Visual check: Compare the entered data against its source by eye. Double entry: Enter data twice and compare the copies for a match. Both seek transcription errors, not truth.

47–57 min · Individual assessment

6. IGCSE exam challenge · 12 marks

Write your own answers before opening the mark scheme.

Reveal mark scheme
  1. 2: Validation tests whether data meets predefined rules (1); verification checks accurate copying/entry (1).
  2. 3: Range check (1); minimum 0 (1); maximum 100 (1).
  3. 3: Any three distinct, correctly described validation checks relevant to student records (1 each).
  4. 2: Enter twice (1); compare entries to detect mismatches (1).
  5. 2: Calculated from other digits using an algorithm (1); helps detect input/scanning errors (1).
57–60 min · Individual reflection

7. Exit ticket

🏠 Homework + extension

Design a school library registration system with at least four validation checks and one verification method. Write pseudocode for two checks and explain why they matter.

ISBN-13 check-digit investigation

For the first 12 digits 978030640615, multiply digits alternately by 1 and 3, then add. The weighted sum is 93, so the final digit must be 7 to make a multiple of 10. Full ISBN-13: 9780306406157.

Challenge: Change one digit. Does the original check digit still pass?
