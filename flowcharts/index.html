Lesson 1 · 60 minutes

Flowchart Fundamentals

Goal: Identify symbols, follow control flow and design sequential flowcharts.

1. Decode the symbols 0–5 min · pairs

Match the five symbols to Start/End, Input/Output, Process, Decision and Flowline.

Check the symbol key

A Start/End (terminator); B Input/Output; C Process; D Decision; E Flowline.

Peer test: Price = 12, Quantity = 3. Expected output = 36.

4. Flowchart Design Sprint 30–50 min · independent + peer review

Choose two challenges, draw flowcharts, then swap and trace with test values.

Bronze: Input length and width; calculate rectangle area.
Silver: Input three marks; calculate total and average.
Gold: Convert Celsius to Fahrenheit using F = (C × 9/5) + 32.

Test values: Bronze: 7 and 4 → 28. Silver: 60, 75, 90 → total 225, average 75. Gold: 20°C → 68°F.

5. Flowchart Error Detective 50–60 min · pairs

Student challenge: This flowchart should input the length and width of a rectangle, calculate the area, and display it. It contains five mistakes. Identify each mistake, explain how to fix it, and redraw the flowchart correctly.

Write the five mistakes and their corrections:

Teacher answer key — reveal after discussion
  1. Missing Start symbol: add a terminator before input.
  2. Output Area occurs before the calculation: move it after calculating Area.
  3. Output Area uses a rectangle: use an input/output parallelogram.
  4. Area calculation uses a diamond: use a process rectangle.
  5. Missing End symbol: add a terminator at the end.

Correct sequence: Start → Input Length, Width → Area ← Length × Width → Output Area → End. The extra "Complete" output is optional.

Lesson 2 · 60 minutes

Decisions and Selection

Goal: Draw decision diamonds, label branches and trace IF / ELSE logic.

1. Choose your path 0–5 min

A student passes if their mark is 50 or more. Predict the output for 35, 50 and 82. Why is a decision required?

2. Explore a decision flowchart 5–15 min

65 → PASS

Test boundary values: 49, 50 and 51. Explain why 50 is a pass.

3. Decision Card Challenge 15–30 min · groups

Choose two problems and draw branching flowcharts:

  1. Classify a number as positive, negative or zero.
  2. Give a discount when age is at least 65.
  3. Check whether an integer is even or odd.
  4. Check whether an entered password matches a stored password.
Peer-test with boundary values: 0, 65, 64, odd/even integers, correct/incorrect passwords.

Test marks 49, 50, 59, 60, 79, 80 and 100. Explain why a binary decision diamond normally has two outgoing branches.

Lesson 3 · 60 minutes

Loops and Repetition

Goal: Use loops, counters, accumulators and termination conditions.

1. Spot the repetition 0–5 min

How could a flowchart input 30 marks without drawing 30 input shapes? What determines when to stop?

2. Trace a counting loop 5–15 min

Study the diagram. The increment step is missing. Where should Count ← Count + 1 go?

Not started. Predict the outputs.
Show correction

Insert Count ← Count + 1 after Output Count and before the arrow returns to the condition. The loop outputs 1, 2, 3, 4, 5, then terminates when Count becomes 6.

3. Build a counting flowchart 15–30 min

Draw a flowchart that outputs 1 to 10 using a counter and a decision. Trace the counter for each iteration.

Extension: Output even numbers from 2 to 20.

4. Total and Average Challenge 30–50 min

Draw a flowchart to input five marks, calculate their total and average, then output both. Include counter and accumulator initialisation, a loop and the average calculation after the loop.

Test: 10, 20, 30, 40, 50 → Total 150; Average 30.

Debug: Why is Total ← Mark wrong inside the loop?

Teacher solution outline

Start → Total ← 0, Count ← 1 → Decision Count ≤ 5? → Yes: Input Mark → Total ← Total + Mark → Count ← Count + 1 → back to decision → No: Average ← Total / 5 → Output Total, Average → End. Total ← Mark overwrites the running total.

5. Debug and Exit Ticket 50–60 min

Explain the impact of each error: counter never increases; counter starts at wrong value; loop condition is wrong. Define an infinite loop and suggest how to prevent one.

Lesson 4 · 60 minutes

Flowchart Challenges and Debugging

Goal: Combine sequence, selection and iteration; trace and correct complete algorithms.

1. Find the bug 0–5 min

A flowchart for finding the largest of five numbers starts with Maximum ← 0. Why does it fail for −8, −3, −12, −5, −9?

Reveal explanation

The algorithm incorrectly outputs 0. It should input the first value and initialise Maximum to that value, then compare the remaining four values. Correct maximum: −3.

2. Flowchart Detective 5–20 min · groups

For each broken algorithm, explain the error and draw a corrected flowchart section.

A · Count positives

Count increases on every iteration, even when Number ≤ 0.

B · Average five marks

Average ← Total / 5 is inside the loop and is output repeatedly.

C · Find minimum

Minimum is initially set to 0 for a list of positive values.

Teacher correction guide

A: Increment Count only on the Yes branch of Number > 0. B: Calculate and output the average after all five marks have been accumulated. C: Initialise Minimum to the first input value and compare the remaining values.

Design a flowchart that inputs ten examination marks and outputs: total, average, highest, lowest and number of passes (mark ≥ 50).

Test values: 45, 72, 88, 31, 60, 95, 54, 77, 42, 66

Your diagram must include a loop, counter, total accumulator, pass counter and comparisons for highest and lowest. Initialise highest and lowest using the first input mark.

Extension: Add a validation loop so marks outside 0–100 are rejected and do not count towards ten accepted marks.

5. IGCSE-style Assessment 50–60 min · independent

  1. 2 marks: Explain the purpose of a decision symbol and how it affects control flow.
  2. 3 marks: Describe a flowchart that inputs numbers until the sentinel value −1 is entered.
  3. 5 marks: Draw a flowchart that inputs five numbers and outputs how many are greater than 20.
Teacher marking guidance

Q1: Evaluates a condition (1); selects a branch depending on Yes/No or True/False (1).

Q2: Input a number (1); decision tests whether number equals −1 (1); if not, repeat input, otherwise terminate (1).

Q3: Initialise counter to 0 (1); loop over exactly five inputs (1); decision tests Number > 20 (1); increment count only when true (1); output count after loop (1).
